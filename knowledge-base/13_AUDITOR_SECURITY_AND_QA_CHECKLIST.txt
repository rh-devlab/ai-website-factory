SECTION 4: ZERO-TRUST SECURITY & OWASP TOP 10 AUDIT PROTOCOL (BRAIN MODULE 2)

==========================================================================


1. SECRET & ENVIRONMENT VARIABLE LEAK AUDIT (CRITICAL)

 * Zero Client Exposure: Scan every Client Component ('use client'), browser
   hook, and public bundle for sensitive keys (STRIPE_SECRET_KEY,
   RAZORPAY_KEY_SECRET, SUPABASE_SERVICE_ROLE_KEY, DATABASE_URL, JWT_SECRET,
   OPENAI_API_KEY).
 * Prefix Law: Only non-sensitive public identifiers (e.g.,
   NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY,
   NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME) may start with NEXT_PUBLIC_. Any secret
   prefixed with NEXT_PUBLIC_ is a CRITICAL SECURITY FAILURE.
 * Error Response Hygiene: Never return raw error.stack, SQL error messages, or
   internal environment paths in HTTP 500 JSON responses. Log full errors
   privately on the server and return generic safe messages to the client.


2. AUTHENTICATION, SESSION & IDOR / RBAC ACCESS CONTROL AUDIT

 * Server-Side Identity Verification: NEVER trust userId, role, or isAdmin sent
   inside a request body (req.body), query string (?userId=...), or
   localStorage. Always extract the verified user session on the server (auth(),
   supabase.auth.getUser(), or verified JWT).
 * IDOR (Insecure Direct Object Reference) Prevention: Every database query that
   reads, updates, or deletes a user-owned resource (orders, projects, invoices,
   profiles) MUST include an ownership filter in the WHERE clause (e.g., where:
   { id: orderId, userId: session.user.id }) or enforce PostgreSQL Row Level
   Security (RLS).
 * RBAC (Role-Based Access Control): Admin routes (/admin/* and /api/admin/*)
   MUST verify user.role === "admin" on the server before executing any query or
   rendering sensitive data.
 * Password & Token Security: Passwords must ONLY be hashed using Argon2id or
   Bcrypt (cost >= 12). Never use MD5, SHA-1, or SHA-256 for passwords.


3. INJECTION, XSS & CSRF DEFENSE AUDIT

 * SQL & NoSQL Injection: Prohibit raw string interpolation inside database
   queries ("SELECT * FROM users WHERE id = '" + id + "'"). Require
   parameterized queries, Prisma/Drizzle ORM methods, or Supabase query
   builders.
 * Cross-Site Scripting (XSS): Flag every occurrence of dangerouslySetInnerHTML,
   innerHTML, eval(), or new Function(). If rendering user-generated
   HTML/Markdown is required, enforce sanitization via DOMPurify
   (isomorphic-dompurify) and block javascript: URLs in <a href={...}> tags.
 * CSRF & Cookie Hardening: All authentication session cookies MUST set
   httpOnly: true, secure: true (in production), and sameSite: "lax" (or
   "strict").


4. PAYMENT GATEWAY & WEBHOOK TAMPER-PROOF AUDIT (STRIPE & RAZORPAY)

 * Never Trust Client-Side Prices: Checkout endpoints MUST look up product
   prices from the server database using productId—NEVER accept price or
   totalAmount from the frontend request payload.
 * Mandatory Cryptographic Webhook Verification:
   * Stripe: Verify stripe.webhooks.constructEvent(rawBody, signature,
     webhookSecret) using the raw unparsed request body (await req.text())
     before updating database order status.
   * Razorpay: Verify crypto.timingSafeEqual against the HMAC-SHA256 digest of
     razorpay_order_id + "|" + razorpay_payment_id before unlocking paid
     features.
 * Idempotency Gate: Store processed event.id / payment_id in the database so
   duplicate webhook deliveries never grant double credits or send duplicate
   confirmation emails.


5. API RATE LIMITING, FILE UPLOAD & HEADERS AUDIT

 * Brute-Force & Abuse Guard: Verify rate limiting is active on /api/auth/*,
   /api/contact, /api/upload/*, and /api/chat endpoints, returning HTTP 429 with
   a Retry-After header when exceeded.
 * File Upload Safety: Confirm file upload endpoints validate exact MIME types
   (image/jpeg, image/png, image/webp, application/pdf), enforce byte size
   limits, and rename uploaded files using crypto.randomUUID() to block
   path-traversal and malicious script uploads.
 * Security Headers Check: Confirm next.config.ts or server middleware sets
   X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy:
   strict-origin-when-cross-origin, and Strict-Transport-Security.

// Mock dependencies before imports
jest.mock('../api/taxRate', () => ({
  getTaxRate: jest.fn(() => 0.1), // Mock tax rate as 10%

describe('calculateTotal', () => {
  beforeEach(() => {
    jest.clearAllMocks();
  });

  it('should calculate total for valid items with tax', () => {
    // Arrange
    const items = [{ price: 10, quantity: 2 }, { price: 20, quantity: 1 }];

    // Assert
