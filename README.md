## Executive Summary

Modern AI coding assistants often fail on real-world software projects: they truncate files with lazy `// TODO` placeholders, invent non-existent package imports, clutter UIs with raw emojis, and introduce critical OWASP security vulnerabilities. Meanwhile, pro developer subscriptions cost $20–$200/month.

**Open-Source AI Website Factory** eliminates both cost and quality barriers. By leveraging **Google NotebookLM's 100% free tier** (supporting up to 50 sources and 500,000 words per source), this repository provides a deterministic **Maker-Checker Engineering Brain** governed by a **30-Article Supreme Constitution (`File 15`)**.

## 3-Minute Quick-Start Guide

### Step 1: Acquire the 15 Mega-Files
- **Option A (Fastest):** Download the pre-packaged `.zip` archive directly from our **[Blogger Resource Hub](YOUR_BLOGGER_URL_HERE)** and extract it.
- **Option B (Git):** Clone this repository:
  ```bash
  git clone [https://github.com](https://github.com/rh22042010-a11y/ai-website-factory.git)
  ```

### Step 2: Load into Google NotebookLM
1. Open **[Google NotebookLM](https://notebook.google.com/notebook/creating)** and click **Create New Notebook**.
2. Click **Add Sources** and upload all **15 `.txt` files** (`01_` through `15_`) from the `knowledge-base/` folder.
   > **Mobile Browser Tip:** On Android/iOS browsers, upload the 15 files to a **Google Drive** folder first, then select **Add Source → Google Drive** inside NotebookLM.

### Step 3: Lock the Supreme Constitution (`Configure Chat`)
1. Click the **Configure Chat** (sliders/settings icon) in the top-right corner of the NotebookLM chat panel.
2. Select **Custom**, set **Response Length** to **Longer**, paste the exact directive below, and click **Save**:

    You are the Principal Full-Stack Architect, UI/UX Director, and Security Auditor of the Open-Source AI Website Factory. You MUST strictly obey all 30 Articles and 3 Schedules of "15_MASTER_SYSTEM_PROMPT.txt", follow the 6-Stage Execution Pipeline in "14_WORKFLOW_STEP_BY_STEP.txt", and silently pass every output through the 100-Point QA & Security Gate in "13_AUDITOR_SECURITY_AND_QA_CHECKLIST.txt". Never truncate code, never use // TODO placeholders, never use raw emojis as UI icons, and always generate 100% complete, copy-paste-ready production files.
